# 深度计 AA5B 上位机协议（TARGET = 2）

> 用途：直接交给上位机（Qt）开发照着实现。
> 来源：**全部字段与样例均为真机实测**（本次固件 = 集成分支 `b19a70e` 的接线 + 驱动 `9abf64e`，
> 经 USB CDC 在 `COM11` 上抓取；抓取日期 2026-10-06）。凡未实测的内容都在文中显式标注。
> 深度计相关代码：`Core/Inc/ms5837.h`、`Core/Src/ms5837.c`；协议编解码：`Core/Src/sensor_protocol.c`；
> 业务层：`Core/Src/sensor_service.c`。

> **当前硬件更正（2026-10-10）**：本机深度计固定为 MS5837-02BA；最新 H750 源码按该型号直接补偿，
> 不再提供型号确认/查询参数/设置参数 `0x0105`。压力和温度按各自有效位上报，水深使用上电固定空气参考 P0=100965 Pa。
> 参数 `0x0103` 只读；只有用户显式调用 `ZERO_DEPTH` 才会更新本次运行的 P0。启动、连接和重连都不自动采集压力。
> 当前源码已通过 ARM Debug 编译；旧固件实测状态曾为 `0x503`（原始 ADC 有效、补偿与零点无效），新固件部署状态以最新烧录记录为准。
> 下文 `0x933/0x9F3` 等字段样例是旧固件的历史实测，其中 bit11 `MODEL_CONFIRMED` 不适用于新固件。

---

## 1. 物理链路与帧族共存

| 项 | 值 |
| --- | --- |
| 链路 | USB CDC 虚拟串口（设备名 `CAN_To_Uart`，实测枚举为 `COM11`） |
| 串口参数 | 115200 8N1（CDC 下波特率不参与实际速率，按此设置即可） |
| 同一条串口上共存的帧族 | `AA 55` CAN 帧、`AA 58` 心跳、`AA 59` 固件流/日志、**`AA 5B` 传感器协议（本文）** |
| 上行复用方式 | 所有帧**走同一个 USB 发送队列**（255 槽 × 78 字节），按入队顺序串行发出；上位机按 `AA` + 家族字节路由即可 |

深度计只使用 `AA 5B` 帧族，`TARGET` 字段恒为 **2**（`TARGET=1` 是同一条协议上的 IMU，不要混用）。

## 2. 通用帧格式（所有 AA5B 帧一致）

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 1 | 帧头 | 固定 `0xAA` |
| 1 | 1 | 家族 | 固定 `0x5B` |
| 2 | 1 | 版本 | 固定 `0x01` |
| 3 | 1 | `CMD` | 命令码，见 §4 |
| 4 | 1 | `FLAGS` | 见 §3 |
| 5 | 1 | `TARGET` | 2 = 深度计 |
| 6 | 4 | `SEQ` | u32 **小端**；回复原样回显请求的 SEQ |
| 10 | 2 | `LEN` | u16 **小端**，负载字节数（不含帧头与 CRC） |
| 12 | 4 | `TIMESTAMP_US` | u32 **小端**，微秒；语义见 §11 |
| 16 | `LEN` | `PAYLOAD` | 负载，见各命令 |
| 16+`LEN` | 2 | `CRC16` | u16 **小端**，见下 |
| 18+`LEN` | 1 | 帧尾 | 固定 `0x5B` |
| 19+`LEN` | 1 | 帧尾 | 固定 `0xAA` |

* 整帧长度 = `20 + LEN`（最大 `20 + 58 = 78` 字节）。
* **CRC16**：CRC-16/CCITT-FALSE —— 多项式 `0x1021`、初值 `0xFFFF`、不反射、无结束异或；
  计算范围 **偏移 1 ~ 15+LEN**（即从第 2 个字节 `0x5B` 起，到负载最后一个字节），结果**小端**写入。
* 解码校验（不全过就丢帧）：`[0]=0xAA`、`[1]=0x5B`、`[2]=0x01`、`LEN ≤ 58`、
  `[18+LEN]=0x5B`、`[19+LEN]=0xAA`、CRC 一致。

## 3. `FLAGS` 与回复约定

| 值 | 含义 | 实测出现场景 |
| --- | --- | --- |
| `0x01` | 请求（上位机 → 设备） | 上位机发出的所有命令 |
| `0x02` | 成功回复 | `GET_INFO/GET_STATUS/GET_PARAMETER/SET_PARAMETER/START/STOP_STREAM/ZERO_DEPTH` 成功 |
| `0x06` | 错误/未支持回复 | 实测出现在 `SAVE_CONFIG(0x45)`、`RESTORE_DEFAULTS(0x46)`、`CALIBRATE(0x49)`、`SELF_TEST(0x4A)`，均为 `RESULT=1` |
| `0x08` | 遥测（设备主动上报） | `0x82`、`0x83` |

* **回复命令码 = 请求命令码 + 0x40**（例：请求 `0x02` → 回复 `0x42`）。
* 所有回复的**负载第 0 字节固定为 `RESULT`**（§4）。
* 遥测帧没有 `RESULT`，负载第 0 字节就是数据（例 `0x82` 的 `status`）。遥测帧的 `SEQ` 是按 TARGET 各自累加的**流序号**，与请求 SEQ 无关。

### `RESULT` 码表

| 值 | 名称 | 含义 | 实测例子 |
| --- | --- | --- | --- |
| 0 | OK | 成功 | 绝大多数回复 |
| 1 | UNSUPPORTED | 该命令/参数未实现 | `SAVE_CONFIG(05)`、`RESTORE_DEFAULTS(06)`、`CALIBRATE(09)`、`SELF_TEST(0A)` |
| 2 | BAD_VALUE | 参数非法 | 例如密度填 5000、OSR 填 3000 |
| 3 | BUSY | 设备忙 | （未实测） |
| 4 | TIMEOUT | 超时 | 例如深度计未绑定时 |
| 5 | OFFLINE | 传感器离线 | （未实测） |
| 6 | IO_ERROR | 总线错误 | （未实测） |
| 7 | UNCONFIRMED | 未确认 | （未实测，IMU 用） |
| 8 | NOT_READY | 数据尚未就绪 | **`GET_PARAMETER 0103` 实测返回 `08`**（尚未采集水面零点） |
| 9 | PIN_BLOCKED | 被管脚占用 | IMU 专用 |

## 5. 参数表（`GET/SET_PARAMETER`）

类型码（实测）：`02` = u8，`04` = u16，`07` = f32（其余类型码未实测）。

| 参数 ID | 名称 | 类型 | 取值 | 默认 | 实测回读 |
| --- | --- | --- | --- | --- | --- |
| `0x0001` | 输出率 | u16 | 1 ~ 100 Hz，**上限由当前 OSR 决定**（见 §5.1；不满足预算返回 `BAD_VALUE`） | 25 | `00 01 00 04 02 19 00` → **25 Hz** |
| `0x0101` | OSR | u16 | 256 / 512 / 1024 / 2048 / 4096 / 8192 | 4096 | `00 01 01 04 02 00 10` → **0x1000 = 4096** |
| `0x0102` | 水密度 | f32 | 900 ~ 1300 kg/m³ | 1029 | `00 02 01 07 04 00 A0 80 44` → **1029.0** |
| `0x0103` | 水面零点压力 | f32 | 10000 ~ 200000 Pa，只读 | 100965 Pa 固定空气参考 | 复位默认恢复固定参考；需要现场修正时通过 `ZERO_DEPTH` 更新 |
| `0x0104` | 滤波系数 K | f32 | 0 ~ 0.99 | 0 | `00 04 01 07 04 00 00 00 00` → **0.0**（不滤波） |

> `GET_PARAMETER` 的回复 = `RESULT(1) + ID(2) + TYPE(1) + LEN(1) + VALUE`；
> `SET_PARAMETER` 的请求负载就是 `ID(2) + TYPE(1) + LEN(1) + VALUE`，回复原样回显。
> 当前固件不开放 `SET_PARAMETER 0103/0105`；前者只读、后者不再支持。

### 5.1 输出率与 OSR 的相互约束（**真机实测**）

每得到一个样本需要两次转换（D1 压力 + D2 温度），所以输出率受当前 OSR 的转换时间硬约束。
驱动按 `2 × (该 OSR 最大转换时间 + 1 ms 余量) + 2 ms ≤ 1000 / 输出率` 检查，
不满足就返回 `RESULT=2 BAD_VALUE`。
**服务层原先还有一道硬编码的 50 Hz 钳位，已解除**（改为使用驱动常量 `MS5837_OUTPUT_RATE_HZ_MAX`），
所以现在 100 Hz 是可达的——但只在 OSR 足够小的时候。

02BA（型号 = 2）实测上限：

| OSR | 实测允许的最高输出率 | 实测帧率证据 |
| --- | --- | --- |
| 256 | 100 Hz（驱动上限） | 未单独测（余量最大） |
| **512** | **100 Hz** | 4 s 收到 400 帧 = **100.0 Hz** |
| **1024** | **100 Hz** | 4 s 收到 398~400 帧 = **99.5~100.0 Hz**（预算正好用满，余量为 0） |
| 2048 | **71 Hz**（72 Hz 被拒） | 4 s 收到 285 帧 = **71.3 Hz** |
| 4096（默认） | **45 Hz**（46 Hz 被拒） | 4 s 收到 182 帧 = **45.5 Hz** |
| 8192 | 25 Hz（公式上限；`SET osr=8192` 实测成功，未单独测帧率） | —— |

**设置顺序很重要**（驱动会对"当前速率 + 目标 OSR"做一致性检查，两个方向都查）：

* 要**提高输出率**：先把 OSR 降到能容纳该速率的值，再设输出率。
  （例：`SET 0101=512` → `SET 0001=100`）
* 要**提高 OSR**：先把输出率降到能容纳该 OSR 的值，再设 OSR。
  （例：`SET 0001=10` → `SET 0101=8192` → `SET 0001=25`）
* 顺序反了不是故障：被拒的组合返回 `RESULT=2`，**已生效的值保持不变**；上位机应把回显值与期望值比对。

**100 Hz 下命令通道依然可靠**（实测）：在 100 Hz 遥测洪流下连续发 20 次 `GET_STATUS` → **20/20 收到回复**；
把速率降回 10 Hz 再测同样 20/20。所以上位机可以"边收 100 Hz 数据边下命令"。

## 8. 状态字位定义（`status`，u32）

| 位 | 名称 | 含义 |
| --- | --- | --- |
| 0 | `ONLINE` | 传感器在线 |
| 1 | `RAW_VALID` | 原始 D1/D2 有效 |
| 2 / 3 | （IMU 用：四元数/欧拉角） | 深度计不使用 |
| 4 | `PRESSURE_VALID` | 压力有效 |
| 5 | `TEMPERATURE_VALID` | 温度有效 |
| 6 | `DEPTH_VALID` | 深度有效（需已归零） |
| 7 | `ZERO_VALID` | 零点已采集 |
| 8 | `PROM_VALID` | PROM 读取且 CRC4 通过 |
| 9 | `PIN_BLOCKED` | 深度计不使用 |
| 10 | （保留） | 当前固件固定型号，不使用 |
| 11 | （保留） | 当前固件固定型号，不使用 |

当前固件未建立 P0 时，正常补偿状态为 `0x00000133` = `ONLINE|RAW_VALID|PRESSURE_VALID|TEMPERATURE_VALID|PROM_VALID`。
显式水面归零后，正常状态含 `DEPTH_VALID|ZERO_VALID`（相应状态为 `0x000001F3`）。

## 11. 时间戳语义（重要）

`TIMESTAMP_US`（帧头偏移 12）= **数据产生时刻**，不是发送时刻：

| 帧 | 时间戳取值 |
| --- | --- |
| `0x82` | 该样本 **D2 结果读完那一刻**的 `HAL_GetTick()` × 1000（分辨率 1 ms，u32 微秒值，约 71.6 分钟回绕一次） |
| `0x83` | 生成该状态帧的时刻 |
| 命令回复 | **回复生成时刻**（实测 `GET_INFO` 回复 `TIMESTAMP_US=2091505000` = 上电后 2091.5 s，即当刻） |

也就是说：`0x82` 的时间戳直接可用于"这条数据是什么时候测出来的"，
上位机做时间对齐/延迟统计时**不要**用接收时间代替。

## 12. 推荐交互时序

1. **连接后**：设备默认**会自动开始推流**（链路建立即开流），所以你会立刻收到 `0x82`/`0x83`；
   不想要就发 `STOP_STREAM`。
2. `GET_INFO`：确认 `sensor_type=2`；固件型号固定为 02BA，不需要确认或设置型号。
3. 等 `GET_STATUS.status` 出现 `PRESSURE_VALID | TEMPERATURE_VALID | PROM_VALID`；当前固件上电后即按 02BA 补偿。
4. 使用固件固定空气参考 P0=100965 Pa。只有现场确需修正且探头确实位于空气/水面参考处时，才显式发一次 `ZERO_DEPTH`。
5. `ZERO_DEPTH` 成功后等待新鲜 `0x82`，确认 `ZERO_VALID | DEPTH_VALID` 后再使用水深；连接与重连不会自动归零。
6. `0x0103` 只读，`0x0105` 不支持；需要调整采样率、OSR 或滤波时仍使用 `0001`、`0101`、`0104`。

## 13. 上位机必须知道的注意事项

1. **帧可能偶尔丢失（设计如此）**：传感器帧入队前有一道背压 —— 当 USB 发送队列占用 ≥ 25/255 时，
   传感器帧直接丢弃（`sensor_board.c:104`），保证 CAN/固件流不被传感器饿死。
   所以"偶尔少一帧 `0x82`"是正常的，用 `sample_seq`/`SEQ` 判断连续性即可。
2. **无参数持久化**：现场 `ZERO_DEPTH` 更新值和其他可调参数保存在 MCU RAM；复位后 P0 回到固件固定空气参考 100965 Pa，型号仍为编译期固定 02BA。
   正常启动不需重新归零；若显式清除 P0 导致 `ZERO_VALID=0`，再由操作者决定是否在空气/水面重采。
3. **旧固件历史状态**：旧固件在没有 P0 时会报告 `depth_*` 无效；当前源码启动已有固定 P0，首个有效补偿样本即可计算水深。
4. `GET_PARAMETER 0103` 正常返回只读 P0；只有显式清除导致无效时才返回 `RESULT=8 NOT_READY`。`SET_PARAMETER 0103` 始终不支持。
5. 参数非法（如密度 5000、OSR 3000、输出率 200）→ `RESULT=2 BAD_VALUE`，
   且**设备端数值不变**；上位机应把回显值和期望值比对。
6. `CALIBRATE`/`SELF_TEST`/`RESTORE_DEFAULTS`/`SAVE_CONFIG` 对深度计**实测统统 `RESULT=1 UNSUPPORTED`**，
   不要在上位机暴露成可用按钮。
7. `0x83` 的 `age_ms` 为 `0xFFFFFFFF` 表示"还没有任何样本"（别当成 49 天的延迟）。
8. **要 100 Hz 就先降 OSR**：`SET 0101`=512 或 1024（02BA），再 `SET 0001`=100；顺序反了会被 `RESULT=2` 拒绝（见 §5.1）。默认 OSR=4096 下最高只有 45 Hz，100 Hz 在物理上不可能。
9. **复位后型号与空气参考固定**：`model=2`、`OSR=4096`、`rate=25`、`P0=100965 Pa`；上位机连接无需设型号，也不会自动采集新的压力。现场修正仅由操作者显式调用 `ZERO_DEPTH`。
