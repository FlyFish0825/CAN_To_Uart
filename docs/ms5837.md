# MS5837 深度计驱动（I2C3）接口与集成说明

驱动主体位于 `Core/Inc/ms5837.h` 和 `Core/Src/ms5837.c`；I2C 事务层已并入驱动文件。2026-10-10 固定型号修正
另增加主机回归 `tests/ms5837_fixed_model_host_test.c` 及运行脚本。本文保留数据手册核对与历史测试记录，当前硬件行为以本页开头的更正为准。

> **当前硬件策略更正（2026-10-10）**：实机只有一只 MS5837-02BA，固件运行时型号固定为 02BA，
> 删除了型号确认/选择/SET_PARAMETER 0105。P0 沿用设备当前有效值且只读；只有显式 `ZERO_DEPTH`
> 会用当时有效压力采集新零点。连接、启动、重连和恢复采样参数都不自动改写或清除 P0。
> P0 仍保存在 MCU RAM，掉电后若设备没有有效 P0，必须由操作者确认探头在空气/水面参考处后再决定是否手动采集；
> 固件不会写入固定的 101325 Pa 或历史压力替代现场基准。下文 30BA 公式和旧型号确认日志只作历史/纯公式校验记录，不是本机运行选项。
> 固定型号 H750 源码本次已通过 ARM Debug 编译，尚未烧录；机器人仍运行旧固件。实机只读状态曾为 `0x503`，D1/D2 有效但压力补偿和 P0 无效。

> 文件名说明：**本模块没有单独的总线文件，也不叫 `i2c.c/i2c.h`**，因此与 STM32CubeMX 生成的
> `Core/Src/i2c.c`、`Core/Inc/i2c.h`（`MX_I2C3_Init` / `HAL_I2C_MspInit`）不存在文件名或符号冲突。
> **I2C3 的 HAL 初始化（GPIO/时钟/时序）由集成方（协调人）负责**，本模块只接收初始化好的 `I2C_HandleTypeDef *`。

## 1. 硬件与总线约定

| 项目 | 取值 | 依据 |
| --- | --- | --- |
| 总线 | I2C3 | 协调文档（深度计挂在 PA8/PC9 的 I2C3） |
| SCL | PA8 | 同上 |
| SDA | PC9 | 同上 |
| 7 位地址 | 0x76（HAL 8 位写地址 0xEC） | MS5837-30BA/02BA 数据手册：`1110110x` |
| 时钟 | 集成方现配 ≈170 kHz（`Init.Timing=0xF0521317`，I2C3 内核=APB1 120 MHz） | 数据手册上限 400 kHz |
| 上拉 | SDA/SCL 各接 3.3 V 上拉（4.7k~10k） | 硬件常识，非本模块代码职责 |
| 中断 | **使用 I2C 事件/错误中断（IT 异步）** | 见 §3.0；不需要 DMA |

总线层把 7 位地址左移一位交给 HAL，调用方只关心 `I2C_BUS_MS5837_ADDRESS7 = 0x76`。
它不定义也不调用 `MX_I2C3_Init`，不与 CubeMX 生成的 `i2c.c` 争符号。

## 2. I2C 事务层（已并入 `ms5837.c` / 接口在 `ms5837.h`）

对外**只保留 4 个函数 + 2 个中断转发入口**：

```c
void           I2c_Init(I2C_HandleTypeDef *handle);   /* 绑定 HAL 句柄(NULL=卸载)，并按实例使能 EV/ER 中断 */
uint8_t        I2c_IsReady(void);
I2cBusResult_t I2c_SetDevice(uint8_t address7);       /* 0x08~0x77，非法返回 PARAM */
uint8_t        I2c_GetDevice(void);
void           I2c_EvIrqHandler(void);                /* 供集成方自己的中断服务函数调用 */
void           I2c_ErIrqHandler(void);
```

* 结果码：`I2C_BUS_OK / NOT_READY / PARAM / BUSY / TIMEOUT / ERROR`（由 `HAL_StatusTypeDef` 映射）。
* **短超时**：`I2C_BUS_DEFAULT_TIMEOUT_MS = 5 ms`，上限 `I2C_BUS_MAX_TIMEOUT_MS = 50 ms`；
  超时不再阻塞主循环，而是由 `Ms5837_Process()` 内部的 `I2c_Process()` 到点发 `HAL_I2C_Master_Abort_IT`。
* 单次事务上限 `I2C_BUS_MAX_TRANSFER = 16` 字节（MS5837 最长事务只有 3 字节）。
* 提交/轮询接口（`I2c_Submit/GetPhase/GetResult/Process`）现在是**文件内部 static**，驱动自己用，
  不再对外暴露；原来的同步包装 `I2c_Write/Read/WriteRead` 已删除。
* 三个可调宏：`I2C_BUS_DEFINE_IRQ_HANDLERS`（默认 1：由本文件提供 `I2C3_EV/ER_IRQHandler`）、
  `I2C_BUS_IRQ_PRIORITY`（默认 5）、`I2C_BUS_ENABLE_NVIC`（默认 1）。
* 主机测试替身宏 `I2C_HOST_TEST` 已随测试文件一起移除：本模块现在固定使用真实 HAL。

## 3. ms5837.h / ms5837.c（驱动）

### 3.0 中断（IT）异步架构与时间戳口径

**主循环零等待**：所有 I2C 收发都走中断异步——驱动只调用 `I2c_Submit()` 提交事务，
随后状态机进入 `BUS_WAIT`；**只有当 `I2c_GetPhase()==DONE`（中断回调已落地）时才处理结果**，
`BUSY` 时本拍直接返回。因此 `Ms5837_Process()` 里没有任何自旋或 `HAL_Delay`：

```
IDLE ──提交 D1 命令──▶ BUS_WAIT ──完成──▶ CONVERT_D1 ──到点提交 ADC 读──▶ BUS_WAIT ──完成──▶
     ──提交 D2 命令──▶ BUS_WAIT ──完成──▶ CONVERT_D2 ──到点提交 ADC 读──▶ BUS_WAIT ──完成──▶ 出帧
```

* 事务在飞期间的“这是干什么的”由 `pending_action` 记录；一次提交→一次完成回调→一次分派。
* 卡死（SCL 被拉低/进水短路）：不再阻塞主循环，`I2c_Process()`（在 `Ms5837_Process()` 内每拍调用）
  到点发 `HAL_I2C_Master_Abort_IT`，结果由 `HAL_I2C_AbortCpltCallback` 落地为超时。
* **弃单清理**：事务在飞时若配置变化或重新 `Init()`，状态机会离开 `BUS_WAIT`，此时
  `Ms5837_Process()` 会把没人认领的 `DONE` 结果取走丢弃，否则总线层会一直停在 `DONE` 卡住后续提交。
* 事务在飞时改 OSR/型号：转换命令已发则按“已发出的那条命令”保守补足等待（未知型号取较大值）；
  若在飞的是结果读取，则丢弃半截并立即用新配置重开，**绝不跨配置配对 D1/D2**。
* 代价与差异（相对同步版）：每个事务需要两次 `Ms5837_Process()` 调用（提交、分派），
  因此样本时间戳与最小转换等待整体平移约 1 ms（实测 40 ms 间隔不变、最小等待 12 ms ≥ 要求 11 ms）；
  `Ms5837_Init()` 只保证“命令已提交”，总线错误在下一次 `Ms5837_Process()` 才落地为错误码/状态位。

**时间戳**：`Ms5837Sample_t.timestamp_ms`（u32）在 **D2 结果读完那一刻**取 `HAL_GetTick()`，
是“本次测量完成时刻”，`Ms5837_GetSampleAgeMs()` 基于它计算。AA5B 帧头的 `TIMESTAMP_US:u32`
由协议层填（当前分辨率 1 ms），**0x82 负载本身不带样本时间戳字段**；若上位机需要“样本自带时间戳”，
建议在 0x82 负载尾部追加 4 字节 u32（属协议层改动）——驱动的该字段随时可提供，也可用于对齐/丢帧判断。
第 7 节的手动/原始访问回复同样预留 4 字节时间戳槽位。

### 3.1 生命周期

```c
Ms5837Result_t Ms5837_Init(void);   /* 在 I2c_Init() 之后调用；发起软复位，不阻塞 */
void           Ms5837_Process(void);/* while(1) 里持续调用；推进复位/PROM/采样状态机 */
```

`Ms5837_Init()` 只发复位命令（0x1E）并记录 `deadline = now + 10 ms`，随后由 `Ms5837_Process()` 逐字读取 PROM（0xA0..0xAC）并做 CRC4 校验。整个初始化**不阻塞**；`Process()` 每次最多做 1~3 次短 I2C 事务。

### 3.2 数据

```c
Ms5837Result_t Ms5837_GetSample(Ms5837Sample_t *sample); /* 无样本返回 NO_SAMPLE */
uint32_t       Ms5837_GetStatus(void);                   /* 见 3.4 状态位 */
uint32_t       Ms5837_GetSampleAgeMs(void);              /* 从未采样返回 0xFFFFFFFF */
uint8_t        Ms5837_HasNewSample(void);
void           Ms5837_ClearNewSampleFlag(void);
Ms5837Result_t Ms5837_GetStats(Ms5837Stats_t *stats);    /* sample_seq/good_frames/errors/... */
Ms5837Result_t Ms5837_GetProm(uint16_t prom[8]);         /* PROM 未验证通过时返回 NOT_READY */
```

`Ms5837Sample_t`：`status, sequence, timestamp_ms, d1, d2, pressure_raw, temperature_centi_c,
pressure_pa, temperature_c, depth_raw_m, depth_filtered_m, surface_pressure_pa, model, prom[8]`。

* 本机固定 02BA，`pressure_raw` 单位为 0.01 mbar，`pressure_pa = pressure_raw`（1 Pa/LSB）。
* **缺失值一律是 NaN**（`MS5837_IS_NAN(x)`），绝不用 0 冒充。
* `GetSample()` 返回的 `status` 是调用时刻的实时状态字，用于判断数据新鲜度。

### 3.3 零点与深度

```c
Ms5837Result_t Ms5837_Zero(void);         /* 用最近一次有效压力显式建立零点（AA5B ZERO_DEPTH） */
Ms5837Result_t Ms5837_ClearZero(void);
uint8_t        Ms5837_IsZeroValid(void);
```

* 设备已有 P0 时直接沿用；没有有效 P0 时 `ZERO_VALID = 0`、深度为 NaN，`GetParam(0103)` 返回 `ERR_NO_ZERO`。通用参数 `0103` 只读。
* 只有显式 `ZERO_DEPTH` 会用最近一次有效压力采集新 P0；内部校验有限值与 **10000~200000 Pa**：测量压力越界时返回 `MS5837_ERR_PARAM` 且不建立零点，
  避免出现“ZERO 成功、但 `GET_PARAMETER(0103)` 认为越界”的矛盾状态；已有的有效零点不会被一次失败的 Zero 破坏。
* `h = (P - P0) / (rho × 9.80665)`，正数向下，不夹紧负值（水面波动时允许负深度）。
* 滤波：`y = FILTER_K × y_prev + (1 - FILTER_K) × x`；默认 `FILTER_K = 0`（等于原始深度）；手动重新采集零点后滤波重新起步。

### 3.4 型号、参数与状态位

```c
uint8_t        Ms5837_GetModel(void);             /* 固定返回 2（MS5837-02BA），仅用于 GET_INFO 描述 */
Ms5837Result_t Ms5837_SetOsr(uint16_t osr);      /* 256/512/1024/2048/4096/8192，默认 4096 */
Ms5837Result_t Ms5837_SetOutputRateHz(uint16_t); /* 1~100，默认 25 */
Ms5837Result_t Ms5837_SetWaterDensity(float);    /* 900~1300 kg/m3，默认 1029 */
Ms5837Result_t Ms5837_SetFilterK(float);         /* 0~0.99，默认 0 */
Ms5837Result_t Ms5837_SetParam(uint16_t param_id, uint8_t type, const void *value, uint8_t length);
Ms5837Result_t Ms5837_GetParam(uint16_t param_id, uint8_t *type, uint8_t *length, uint8_t value[4]);
Ms5837Result_t Ms5837_RestoreDefaults(void);     /* OSR/输出率/密度/滤波回默认，保留 P0 */
```

参数 ID / 类型码与 AA5B v1 一致：`0001 OUTPUT_RATE_HZ:u16`、`0101 DEPTH_OSR:u16`、
`0102 WATER_DENSITY:f32`、`0103 SURFACE_PRESSURE:f32`、`0104 FILTER_K:f32`。
`0103` 只读，`SET_PARAMETER 0103` 与 `0x0105` 查询/设置均返回 UNSUPPORTED；P0 只能通过显式 `ZERO_DEPTH` 改变。
其他参数仍只存在 MCU RAM，无设备回读；零点未建立时 `GET_PARAMETER 0103` 返回 `ERR_NO_ZERO`。

采样率与 OSR 互相约束，周期预算为
`2 × (最大转换时间 + 1 ms 余量) + 2 ms 事务预算 ≤ 1000 / f_s`，
不满足时 `SetOsr`/`SetOutputRateHz` 返回 `MS5837_ERR_PARAM`（拒绝，而不是偷偷降速）；运行时预算固定按 02BA 计算：

| OSR | 02BA 最大转换时间 | 周期预算 | 运行时最高采样率 |
| --- | --- | --- | --- |
| 256 | 0.56 ms | 6 ms | 100 Hz |
| 512 | 1.10 ms | 8 ms | 100 Hz |
| 1024 | 2.17 ms | 10 ms | 100 Hz |
| 2048 | 4.32 ms | 14 ms | 71 Hz |
| 4096 | 8.61 ms | 22 ms | 45 Hz |
| 8192 | 17.20 ms | 40 ms | 25 Hz |

默认 25 Hz / OSR4096 满足（22 ms ≤ 40 ms）。运行预算只按本机固定 02BA 计算。

时序实现要点（评审后修正）：

* **周期锚定在周期开始时刻**：`cycle_start_ms` 在发出 D1 命令时记录，下一帧在
  `cycle_start_ms + 1000/f_s` 触发，因此转换等待不会累加到采样周期上。
  修复前实际间隔是“转换耗时 + 周期”（25 Hz/4096 实测会掉到 ~15–16 Hz）。
  若已经超期（总线卡了一下），直接从当前时刻开始下一帧，**不做补偿性连发追赶**。
* **等待从命令发完之后起算**：每次转换的 `deadline = HAL_GetTick()（命令发完之后）+ ceil(最大转换时间) + 1 ms`，
  避免“发命令之前的 now”造成的毫秒相位提前读。
* **转换途中改 OSR：延迟丢弃半周期（`DISCARD_WAIT`）**。已发出的转换命令对应的等待是按旧配置算的，
  而手册第 11 页说明芯片在转换完成前一直 busy、重发转换或提前读 ADC 都会得到错误结果。
  因此 `SetOsr()` 在 `CONVERT_D1`/`CONVERT_D2` 状态下只清掉半截 D1/D2 并进入 `DISCARD_WAIT`：
  **保持原 deadline 继续等**，到点后再用新配置重新走完整周期；期间不重发转换、不读 ADC，
  换成更短 OSR 也不会缩短旧转换的等待。采样率（`SetOutputRateHz`）变化不影响转换等待，当前周期照常完成。
  回归 `BusyDeviceNoEarlyRestart` 用“芯片 busy_until”仿真覆盖 D1/D2 期间 8192→256、256→8192、02BA↔30BA、
  连续 4 次改配置与 tick 回绕共 8 个场景。
* 主机测试用逐毫秒推进、每次 I2C 事务真实消耗 1 ms 的仿真验证：
  25 Hz 连续 6 帧间隔实测 **40/40/40/40/40 ms**，最小“命令→读 ADC”等待 **11 ms**（要求 ≥ 9.04→10 + 1 ms），提前读 ADC 次数 0。

状态位（与 AA5B v1 对齐，本模块只操作下面这些）：

| 位 | 名称 | 含义 |
| --- | --- | --- |
| 0 | ONLINE | 最近一次总线访问成功 |
| 1 | RAW_VALID | 有可信 PROM + D1/D2 |
| 4 | PRESSURE_VALID | `pressure_pa` 有效（固定 02BA 补偿成功） |
| 5 | TEMPERATURE_VALID | `temperature_c` 有效（固定 02BA 补偿成功） |
| 6 | DEPTH_VALID | 深度有效（压力有效且零点有效） |
| 7 | ZERO_VALID | 零点已显式采集/设定 |
| 8 | PROM_VALID | PROM CRC4 通过 |
| 10–11 | 保留 | 当前固定型号实现不使用 |

总线错误会清掉 0/1/4/5/6 位（数据新鲜度），保留仍有效的 ZERO_VALID/PROM_VALID 状态。

### 3.4.1 假数据防护（评审后新增）

| 情况 | 处理 |
| --- | --- |
| PROM CRC4 不符 | 不置 `PROM_VALID`，不发布任何测量值，按重试间隔重读 PROM，计入 `crc_errors` |
| PROM CRC 通过但 C1~C6 **全 0 或全 0xFFFF** | 视为“假 PROM”（I2C 卡死/空器件特征），同样不置 `PROM_VALID`、不上线，计入 `crc_errors`，`last_error = ERR_CRC` |
| D1 或 D2 读到 **0x000000 或 0xFFFFFF** | 判定为无效转换：不发起后续步骤/不发布样本，`last_error = ERR_NOT_READY`，保留 `ONLINE`，已发布样本的测量字段置回 NaN（`sequence` 不推进） |
| `Ms5837_Compensate()` 输入超过 24 位、或等于 0 / 0xFFFFFF | 返回 0，不写任何输出（纯函数也拒绝，避免集成方绕过驱动直接拿到“有效假数据”） |

## 4. 数据手册核对记录（官方文档，未使用厂家 AT 指令）

本驱动只用数据手册的 I²C 命令与整数补偿公式，不涉及任何 AT/UART 指令。

来源（PDF 仅用于离线核对，未纳入仓库）：
* MS5837-30BA 数据手册（TE，文档日期 03/12/2015）。
* MS5837-02BA01 数据手册（TE，**06/2017**，16 页，带 “Downloaded from Arrow.com” 页脚）——**由用户提供**，
  统筹方已把关键页转录与页面图核对结果记录在 `docs/MS5837-02BA01-user-manual-task-20261006.md`（本次任务的核对输入，非原 PDF 副本）。
  本轮 02BA 的一阶/二阶公式、单位、最大转换时间、I2C 命令与 PROM/CRC 均按该手册第 2/7/8/9/10/12 页重新核对。

核对结论：

1. **命令集与地址**：复位 0x1E、PROM 读 0xA0..0xAC（**7 个字，物理 PROM 只有 7 个 16 位字**）、ADC 读 0x00、
   D1 转换 0x40/0x42/…/0x4A、D2 转换 0x50/0x52/…/0x5A（OSR 256→8192）；地址 `1110110x`。
   驱动**只按顺序读这 7 个地址，绝不读 0xAE**；CRC4 需要的第 8 个数组元素由软件置 0（`prom[7] = 0`），
   设备不提供第 8 个字也能上线（主机测试里仿真设备对 index>6 返回 `HAL_ERROR`，可用于证伪）。
   **手册原文差异（如实记录，不做“整理”）**：02BA01 手册**第 9 页命令编码表写的是 PROM Read `0xA0 to 0xAE`**，
   但**第 10 页明确“总共 7 个地址、112 bit”**、第 12 页 PROM 映射只定义 0..6（0 含 CRC 与 Factory defined，
   1..6 为 C1..C6），且 CRC 示例算法自己要求把 `n_prom[7]` 置 0。因此第 9 页的 `AE` 是编码表范围写法，
   而不是“必须读通第 8 个字才能上线”的要求；本项目按第 10/12 页读 A0/A2/A4/A6/A8/AA/AC 七字。
2. **CRC4**：字 0 高 4 位是 CRC，先清零；第 8 个字置 0；×16 次字节异或 + 多项式 0x3000；
   结果取 `(rem >> 12) & 0x0F`。驱动按此实现（不改调用者的数组，内部用副本）。
3. **一阶补偿**（两型号公式不同）：
   * 30BA：`dT = D2 - C5·2^8`；`TEMP = 2000 + dT·C6/2^23`；
     `OFF = C2·2^16 + C4·dT/2^7`；`SENS = C1·2^15 + C3·dT/2^8`；`P = (D1·SENS/2^21 − OFF)/2^13`（0.1 mbar）。
   * 02BA：`OFF = C2·2^17 + C4·dT/2^6`；`SENS = C1·2^16 + C3·dT/2^7`；`P = (D1·SENS/2^21 − OFF)/2^15`（0.01 mbar = 1 Pa/LSB）。
4. **二阶温补**：
   * 30BA：`TEMP/100 < 20 °C` 时 `Ti = 3·dT²/2^33`、`OFFi = 3·(TEMP−2000)²/2`、`SENSi = 5·(TEMP−2000)²/8`；
     `TEMP/100 < −15 °C` 再叠加 `OFFi += 7·(TEMP+1500)²`、`SENSi += 4·(TEMP+1500)²`；
     高温（≥ 20 °C）分支 `Ti = 2·dT²/2^37`、`OFFi = (TEMP−2000)²/2^4`、`SENSi = 0`。
   * 02BA（**本轮已按用户提供的 02BA01 06/2017 手册第 7 页重新核对**）：只有低温分支
     `Ti = 11·dT²/2^35`、`OFFi = 31·(TEMP−2000)²/2^3`、`SENSi = 63·(TEMP−2000)²/2^5`（第 8 页流程图），
     **没有 30BA 的高温分支，也没有 −15 °C 追加项**；非低温分支 Ti/OFFi/SENSi 必须为 0（不得残留上一帧低温值）。
     此前“来自位图 OCR、尚未核实”的表述已作废。
5. **最大转换时间**（数据手册 ADC 表 Max 列，数据手册注明“I²C 等待时间必须用最大值”）：
   | OSR | 256 | 512 | 1024 | 2048 | 4096 | 8192 |
   | --- | --- | --- | --- | --- | --- | --- |
   | 30BA | 0.60 | 1.17 | 2.28 | 4.54 | 9.04 | 18.08 ms |
   | 02BA | 0.56 | 1.10 | 2.17 | 4.32 | 8.61 | 17.20 ms |
   驱动按“向上取整到毫秒 + 型号未知取较慢一侧”等待，保证不会提前读 ADC。
6. **官方算例**（已进测试）：
   * 30BA：`C1..C6 = 34982,36352,20328,22354,26646,26146`，`D1=4958179`，`D2=6815414`
     → `dT=−5962`、`TEMP=19.81 °C`、`P=3999.8 mbar`（驱动得 `pressure_raw=39998`，即 399980 Pa）。
   * 02BA（第 7 页，**逐项断言**）：`C1..C6 = 46372,43981,29059,27842,31553,28165`，`D1=6465444`，`D2=8077636`
     → `dT=68`、`TEMP=2000`（20.00 °C）、`OFF=5764707214`、`SENS=3039050829`、`P=110002`（1100.02 mbar，1 LSB = 1 Pa）。
7. **02BA01 手册的其他原文事实**（写进文档以免被过度解读）：
   * 第 2 页：“Maximum values must be applied to determine waiting times in I2C communication.”，
     最大转换时间 8192/4096/2048/1024/512/256 → 17.20/8.61/4.32/2.17/1.10/0.56 ms，典型值 16.44/8.22/4.13/2.08/1.06/0.54 ms。
     供电 1.5~3.6 V；第 2 页的 10 bar 属于绝对最大额定值中的 overpressure，**不是工作量程**。
   * 第 3 页：Operating Pressure Range **300..1200 mbar**；Extended Pressure Range / Linear Range of ADC **10..2000 mbar**；
     相对精度按压力/温度区间分别给出，**不能宣称整个 2 bar 量程同一精度**；SCL 最高 400 kHz。
   * 第 1 页的 “13 cm” 是海平面处**空气高度分辨率**，不是水深分辨率；本项目同样**不宣称 0..10 bar / 0..10 m 全程精度**。
   * 第 15 页要求 VDD 附近至少 100 nF 陶瓷去耦（硬件侧，非本模块代码职责）。
   * 第 10 页：上电后应发 Reset 使 PROM 载入；SDA 卡在 ACK 状态时可若干 SCL 后 Reset 或重新上电。
     手册**没有给出 Reset 完成等待时间**，现有 10 ms 是项目保守策略，不是厂商给定值。
8. **第 11 页：转换期间芯片一直 busy**（本轮据此修了一处真实缺陷）：
   * “If the ADC read command is sent during conversion the result will be 0, the conversion will not stop and the final result will be wrong.”
   * “Conversion sequence sent during the already started conversion process will yield incorrect result as well.”
   * “When command is sent to the system it stays busy until conversion is done.”
   实现上“丢弃软件半周期”≠“取消芯片转换”：改 OSR/型号时驱动进入 `DISCARD_WAIT`，**保留旧 deadline**
   （按旧配置算、不会更短的等待），等芯片空闲后才用新配置重新发 D1，因此不会在 busy 期间重发转换或提前读 ADC，
   换成更短 OSR 也不会缩短旧转换的等待。
9. **两个刻意的实现选择**（都有测试覆盖）：
   * 所有 `2^n` 除法按**向负无穷取整**实现（等价数据手册流程图里的 `>> n`）。数据手册 30BA 算例给出
     19.81 °C，只有向下取整才能复现（截断取整会得到 19.82 °C）。`SENS` 中间值也与之吻合。
   * 复位后等待 10 ms 再读 PROM：数据手册未给出具体数值（只要求“上电后发一次复位”），
     10 ms 是保守余量，且这段时间由状态机承担，不阻塞主循环。
8. **数据手册自身的小瑕疵**（不影响实现）：30BA 算例表里 `OFF` 印为 2381326464，按它自己的公式应为
   2381323464；但同表的 `SENS=1145816755`、`P=39998`、`TEMP=1981` 都与公式一致，且用打印的 `OFF/SENS`
   反算 `P` 仍是 39998，因此驱动按公式实现。

## 6. 已知限制

* 本机硬件型号固定为 MS5837-02BA，由固件编译期常量 `MS5837_MODEL_FIXED` 指定；不使用 PROM 阈值猜测，

## 7. 预留（**未实现**）：上位机直连的“原始/手动访问”

定位：**高级调试能力，不属于正常数据通路**。用户 2026-10-06 明确“现有功能保留可用优先，
直连属于高级调试功能”，因此本节只记录设计，**当前代码没有任何手动/原始访问 API，
现有接口与行为不受影响**。要做时按下述契约实现即可，改动只在
`Core/Inc/ms5837.h`、`Core/Src/ms5837.c`（以及可选的 AA5B 路由，属集成方文件）。

### 7.1 器件事实（决定了“直连”只能是这几种操作）

MS5837 **没有任何可写寄存器**，不存在配置/量程/ODR/ID 寄存器，PROM 是工厂 OTA 只读；
它只认 5 类命令字节，且没有回读通道可确认“写入生效”。因此“直连”等价于：

| 直连操作 | 对器件做什么 | 已有等价能力 |
| --- | --- | --- |
| 透传任意 1 字节命令 | 发送主机指定的 cmd（如 `0x1E`） | 无（只有内部状态机发固定命令） |
| 任意读 N 字节 | 读回器件后续返回的原始字节 | 无（`GetProm` 只给 PROM） |
| 手动转换（主机指定 OSR） | 发 `0x40/0x50 + OSR`，等待后读 ADC | 部分：`SetOsr` 影响自动流程 |
| 复位并等待 | `0x1E` + 复位等待 | `Ms5837_Init()`（会重新进入自动流程） |

注意：OSR 不是寄存器，而是**转换命令低 3 位**；“改 OSR”本质就是换命令字节。

### 7.2 建议的驱动侧 API（实现时必须遵守的不变量）

```
Ms5837Result_t Ms5837_SetManualMode(uint8_t enable);   /* 会与自动采样互斥 */
uint8_t        Ms5837_IsManualMode(void);
Ms5837Result_t Ms5837_ManualCommand(uint8_t command);  /* 原样发 1 字节，不解释语义 */
Ms5837Result_t Ms5837_ManualWriteRead(uint8_t command, uint8_t *buffer, uint8_t length);
Ms5837Result_t Ms5837_ManualConvertStart(uint8_t which_d1, uint16_t osr);
uint8_t        Ms5837_ManualBusy(void);                /* 主机必须等它变 0 才能读 ADC */
Ms5837Result_t Ms5837_ManualAdcRead(uint32_t *raw24);
Ms5837Result_t Ms5837_ManualReset(void);               /* 发 0x1E，之后 ManualBusy 直到复位延时结束 */
```

必须保持的不变量（否则会破坏已评审过的保证）：

1. **与自动采样互斥**：进入手动模式时若正处于 `CONVERT_D1/D2`，返回 `MS5837_ERR_BUSY`，
   由主机稍后重试；绝不在芯片忙时插命令（手册第 11 页：转换中重发或提前读都会得到错误结果）。
   手动模式期间 `Ms5837_Process()` 不发起任何自动转换。
2. **时序由服务端强制**：`ManualConvertStart` 记录 `deadline = now + ceil(最大转换时间) + 1 ms`，
   在 `ManualBusy()` 为 1 时 `ManualAdcRead` 返回 `MS5837_ERR_BUSY`——让主机**无法**违反第 11 页规则。
3. **不污染遥测**：手动操作的结果只作为返回值，**不写入 `Ms5837Sample_t`**、不改
   `RAW/PRESSURE/TEMPERATURE/DEPTH/ZERO/PROM` 任何有效位、不推进 `sequence`；
   只允许更新 `ONLINE` 与错误统计（`errors/bus_timeouts/last_error`）。
4. **非阻塞**：全部接口立即返回，等待靠 `ManualBusy()` 轮询，避免堵主循环。
5. **退出即恢复**：`SetManualMode(0)` 后回到 IDLE，按原 OSR/型号在下一拍重新开始干净周期；
   `Ms5837_Init()` 一律退出手动模式。
6. **可编译期裁剪**：建议用 `#if MS5837_ENABLE_MANUAL_ACCESS`（默认 0）包住，正式构建不增代码。

### 7.3 走 AA5B 到 COM11 需要的集成侧改动（**属集成方文件，本分支不动**）

协议层目前只有固定命令，没有透传口。要实现“上位机直接下命令”，需要集成方在
`sensor_service.c` / `sensor_protocol.c` 增加一个命令（建议 `CMD 0x0D RAW_ACCESS`，TARGET=2），
负载为 `op:u8 + 参数`，回复体为 `RESULT + 原样字节`：

| op | 参数 | 行为 | 回复 |
| --- | --- | --- | --- |
| 0 | `enable:u8` | 进/出互斥；转换中返回 BUSY，由上位机重试 | `RESULT` |
| 1 | `cmd:u8` | 透传 1 字节命令 | `RESULT` |
| 2 | `cmd:u8, len:u8` | 发命令后读 `len`(1..16) 字节 | `RESULT + bytes` |
| 3 | `which:u8, osr:u16` | 手动转换（osr 必须是 256..8192 的合法值） | `RESULT` |
| 4 | `—` | 读 ADC 3 字节（`ManualBusy` 时回 BUSY，不代等） | `RESULT + raw24` |
| 5 | `—` | 复位并按复位延时 busy | `RESULT` |

以上每个回复都建议**预留 4 字节时间戳**（`timestamp_ms:u32`，取命令完成时刻），便于上位机把
调试动作与遥测/日志对齐；正式遥测的时间戳仍在 AA5B 帧头。

### 8.3 兼容性提醒

* 这是**破坏性协议变更**：0x82 的 32 字节布局被 0x4D 的 21 字节取代，且默认不再推流。
  **GUI 必须同步改**；旧 GUI 配新固件会看不到深度数据（但也不会误显示，因为不再有 0x82）。
* 若想“零协议改动”的过渡做法：不动布局，只把第 3 条的自动开流去掉 —— 上位机每次想取值就
  `07 → 收几帧 → 08`。代价是交互啰嗦、无法只取需要的字段；字段裁剪必须走 8.1。
* 传感器仍持续采样（温度/压力/深度/零点/滤波语义不变），所以查询式取数不会丢失“是否有效”
  的判断依据：`status` 位永远跟着值一起回。


集成侧还需保证：手动模式期间**遥测不能被当成新鲜数据**（建议：进手动模式时对 TARGET=2 自动
`STOP_STREAM`，或让上位机显式停止并显示“调试模式”），且 `SAVE_CONFIG` 仍为 UNSUPPORTED。
